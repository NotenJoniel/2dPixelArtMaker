# 00. 制作ワークフロー全体概要

本ドキュメントでは、本プロジェクトにおける2Dピクセルアート（ドット絵）アセット制作の全体フローと、人間（ディレクター／開発者）およびAIエージェントの役割分担を定めます。

---

## 1. 基本思想

1. **特定ゲームエンジン非依存（Engine-Agnostic）**
   - 出力アセットは**等倍（1x）の透過PNG**と**標準JSONメタデータ**で構成します。Unity、Godot、Unreal Engine（Paper2D）、RPGツクール、Web（PixiJS / Phaser）、自作エンジンのいずれにも変換・インポートしやすい中立な構造を維持します。
2. **コードによるピクセル描画（Code-Driven Pixel Art）**
   - 基本の描画手段として、Pythonスクリプト（`tools/pixel_canvas.py` 等）によるプログラマティックなピクセル生成を採用します。
   - **再現性**: 描画コード（`workspace/01_raw/`）を残すことで、「色替え（2Pカラー・属性違い）」「装備差分」「キャンバスサイズ調整」「パーツ単位の微修正」をいつでも正確に再実行できます。
   - **厳密性**: 1ドット単位の整数座標とパレットキーを直接指定するため、画像生成AIで頻発するドットサイズ崩れ（Mixels）やアンチエイリアスゴミが原理的に混入しません。

---

## 2. 標準制作の5フェーズ

```text
[Phase 0: 初期方針決定] 必須5項目＋任意項目をアンケートまたは 00_project_brief.md で合意
        ↓
[Phase 1: 詳細仕様策定] AIが 01_art_direction / 02_color_palette 等の技術仕様書へ展開・確定
        ↓
[Phase 2: コード描画]   workspace/01_raw/ に描画スクリプトを作成し 02_work/ へパーツ/フレーム出力
        ↓
[Phase 3: 視覚確認]     workspace/03_preview/ に拡大・合成確認画像を出力し目視レビュー＆改善
        ↓
[Phase 4: 検収・納品]   QA基準を満たした等倍PNG＋JSONを assets/ に出力し validate_assets.py で検証
```

### Phase 0: 初期方針決定・キックオフ（`docs/00_project_brief.md`）
いきなり細かいピクセル数やカラーコードを埋める負担をなくすため、最初に人間が決めるべき**必須5項目**と、AIに任せられる**任意項目**を切り分けてスタートします。

- **開始方法は2通り（どちらでも可）**:
  1. **ファイル記入スタート**: `templates/00_project_brief.template.md` を `docs/00_project_brief.md` にコピーし、必須5項目だけ記入してAIに渡す。
  2. **対話アンケートスタート**: AIに「新しいプロジェクトを始めたい」と話しかけ、AIからの選択式アンケートに答えて `docs/00_project_brief.md` を自動生成させる。
- **必須5項目（後から変えると作り直しになる根幹方針）**:
  1. ゲームジャンルとカメラ視点（横視点 / 見下ろし3/4 / クォータービュー / 正面一枚絵）
  2. 世界観・モチーフと空気感（トーン）
  3. キャラクターの頭身イメージ（2頭身 / 3〜4頭身 / 5〜7頭身）
  4. パーツ分割・アニメーション方針（パーツ分割 / コマ打ち / ハイブリッド）
  5. 最初の制作スコープ（まず何から試作するか）
- **任意項目（空欄＝「AIおまかせ」で自動設計）**:
  - 参考作品イメージ、具体的な画面解像度・タイルpx指定、主線スタイル、キーカラー・色数制限、左右反転の可否など。

### Phase 1: 詳細仕様書への展開（`templates/` → `docs/`）
- Phase 0 の回答をもとに、AIが専門的な技術パラメータ（1080p整数倍スケール解像度、基準タイルpx、カラーランプHEX値、パーツ構成など）を設計し、以下の仕様書を `docs/` に作成します：
  1. `docs/01_art_direction_and_world.md`
  2. `docs/02_color_palette_spec.md`（実体パレットは `assets/palettes/`）
  3. 対象アセットの台帳・個別仕様書（`03_character_list.md`, `docs/characters/<id>.md` 等）

### Phase 2: コードによるピクセル描画（`workspace/01_raw/` → `workspace/02_work/`）
- アセットIDごとに `workspace/01_raw/<asset_id>/gen_<asset_id>.py` を作成します。
- 小さいパーツや顔・アイコン等の繊細な造形は**記号ドットマップ（ASCII Pixel Map）**、体幹や大型構造物・アニメーション変形は**座標プリミティブ＋シェーディング＋自動1pxアウトライン**を組み合わせて描画します。
- パーツ分割対象の場合は、最初からパーツ別レイヤー（関数）として設計し、`workspace/02_work/<asset_id>/` に出力します。

### Phase 3: 拡大プレビューとセルフレビュー（`workspace/03_preview/`）
- 等倍のままでは細部が見えづらいため、必ず **4倍〜8倍にニアレストネイバー拡大した確認用画像**（透過確認用チェッカー背景・1pxグリッド・ピボット十字マーカー付き）を `workspace/03_preview/` に生成します。
- パーツ分割キャラは `tools/preview_rig_composite.py` を用いて、全パーツを `z_index` 順に重ねた合成プレビューと、パーツ一覧展開シートを生成します。
- **AIの必須義務**: スクリプト実行だけで完了とせず、生成されたプレビュー画像を読み取って「頭身バランス」「シルエットの分かりやすさ」「ジャギーの有無」「関節の隙間」を確認し、改善イテレーションを行います。

### Phase 4: 最終書き出し・自動検証（`assets/`）
- 検収を通過した等倍PNGおよびメタデータJSONを `assets/` の所定ディレクトリへ出力します。
- 最後に `tools/validate_assets.py` を実行し、キャンバスサイズ・アルファ値の二値性・パレット外カラーの混入・JSONスキーマ整合性に問題がないことを機械的に保証します。

## 3. 人間とAIの役割分担

| フェーズ | 人間（ディレクター／開発者） | AIエージェント |
| :--- | :--- | :--- |
| **Phase 0: 初期方針決定** | 必須5項目（視点・世界観・頭身・分割有無・初回目標）の選択 | アンケート実施（または記入シート読取）、`00_project_brief.md` 記録 |
| **Phase 1: 詳細仕様策定** | AIが提案した解像度・パレット・個別仕様の確認と承認 | 任意項目の最適補完、`01`〜`06` の詳細仕様書とパレットJSONの自動生成 |
| **Phase 2: コード描画** | 特別なこだわり・モチーフ指示の提示 | 規約・パレットに準拠した描画スクリプト実装、パーツ分割設計 |
| **Phase 3: 視覚確認** | `03_preview/` の確認、修正フィードバック（「目を1px下に」等） | プレビュー生成、視覚セルフレビュー、座標・ドット単位の迅速な修正 |
| **Phase 4: 検収・納品** | 最終承認、ゲームエンジン側への組み込み | `assets/` へのクリーン出力、`validate_assets.py` による品質保証 |
