# 00. 制作ワークフロー全体概要

本ドキュメントでは、本プロジェクトにおける2Dピクセルアート（ドット絵）アセット制作の全体フローと、**どのAIモデルを使っても同じ高品質を安定再現するための3層ガードレール（定量ガイドライン・素体ブループリント・自動スタイル検査）**を定めます。

---

## 1. 基本思想と「AIモデル間の品質再現性」を支える仕組み

1. **特定ゲームエンジン非依存（Engine-Agnostic）**
   - 出力アセットは**等倍（1x）の透過PNG**と**標準JSONメタデータ**で構成します。Unity、Godot、Unreal Engine（Paper2D）、RPGツクール、Web（PixiJS / Phaser）、自作エンジンのいずれにもそのまま組み込めます。
2. **コードによるピクセル描画（Code-Driven Pixel Art）**
   - `tools/pixel_canvas.py` による整数座標・記号ドットマップ描画を基本とすることで、画像生成AIで頻発するドットサイズ崩れ（Mixels）や半透明ゴミの混入を原理的にゼロにします。
   - `PixelCanvas.draw_ascii_map()` は行ごとの文字数不一致を自動検出して即時エラー化するため、LLMがテキストマップ編集時に起こしやすい「1列ズレ事故」を物理的に防ぎます。
3. **3層ガードレールによるモデル非依存の品質維持**
   - **第1層（選択式プリセットと定量数値化）**: 「ファミコン風」「スーファミ風」などの**サイズ規格（`size_preset`）**と、「かわいい系」「かっこいい系」などの**デザインテイスト（`taste_preset`）**を選択式にし、頭:体:足のピクセル数・コア胴体幅・目のドット構成を数値で固定します。
   - **第2層（素体＆歩行ブループリント `tools/character_blueprints.py`）**: AIが白紙キャンバスから目分量で描いて頭身・横向き姿勢・大型ボスの立体感を崩すのを防ぐため、検証済みの日本式ゲーム素体（`M` 人型4方向・`L/XL` 大型ボス構造素体）および **SFC品質の4方向×4コマ歩行サイクル素体（`--walk`）** を起点に衣装・髪型・動きを展開させます。
   - **第3層（造形・仕様ゲートリンター `tools/lint_character_style.py` ＆ `validate_assets.py` ＋ 視覚確認）**: Phase 1 仕様書（`docs/01〜03`）未作成でのフライング描画ブロック、頭幅全域の透過ピンホール、縦2px目の上下1px横ズレ（斜視バグ）、サイズ間延び・寸胴・首伸び・左右完全対称きのこ頭・内部黒横線、および4コマ歩行の「2コマ反復（片足ケンケン）」を機械検査で自動検出し、さらに拡大プレビュー画像の目視確認を必須化します。

---

## 2. 標準制作の5フェーズ

```text
[Phase 0: 初期方針決定] 必須6項目（視点・世界観・サイズ規格・テイスト・分割方針・初回目標）を合意
        ↓
[Phase 1: 詳細仕様策定] AIが character_blueprints.py の定量値を反映した仕様書とパレットJSONを作成
        ↓
[Phase 2: コード描画]   検証済み素体を起点に workspace/01_raw/ の描画スクリプトで 02_work/ へ出力
        ↓
[Phase 3: スタイル検査] lint_character_style.py 実行 ＋ 03_preview/ の拡大画像を目視レビュー＆改善
        ↓
[Phase 4: 検収・納品]   等倍PNG＋JSONを assets/ に出力し validate_assets.py で最終品質保証
```

### Phase 0: 初期方針決定・制作ロスター指定（`docs/00_project_brief.md` ＆ 任意で `docs/00_roster_spec.md`）
- **開始方法は2通り（どちらでも可）**:
  1. **ファイル記入スタート**: `templates/00_project_brief.template.md` を `docs/00_project_brief.md` にコピーして必須6項目にチェックする。さらに作りたいキャラ・モブ・ザコ・ボスの内訳やサイズ区分（`S/M/L/XL`）を1体ずつ細かく指定したい場合は、`templates/00_roster_spec.template.md` を `docs/00_roster_spec.md` にコピーして記入する。
  2. **対話アンケートスタート**: AIに「新しいプロジェクトを始めたい」と話しかけ、選択式アンケートに答える（キャラ数・敵数の指定も「おまかせセット／人数だけ指定／`00_roster_spec.md` で個別指定」から選択可能）。
- **必須6項目**:
  1. **ゲームジャンルとカメラ視点**（横視点 / 見下ろし3/4［4方向］ / クォータービュー / 正面一枚絵）
  2. **世界観・モチーフ**
  3. **サイズ・世代規格（`size_preset`）**:
     - `fc_16x16`（ファミコン / 8-bit風：標準M `16×16` 枠）
     - `sfc_16x24`（スーファミ / 16-bit王道JRPG風：標準M `32×32` 枠・本体 `16×20〜24` px）【標準推奨】
     - `hd2d_18x32`（モダンJRPG / HD-2D風：標準M `48×48` 枠・本体 `18×32` px）
     - `high_32x56`（ハイレゾ5頭身 / GBA・アクション風：標準M `64×64` 枠・本体 `28×54` px）
  4. **デザインテイスト・雰囲気（`taste_preset`）**:
     - `cute`（かわいい系） / `cool`（かっこいい系） / `retro_classic`（レトロ王道系） / `dark_serious`（ダーク・シリアス系）
  5. **パーツ分割・アニメーション方針**（単一コマ打ち / 簡易レイヤー分割 / 多関節ボーン分割）
  6. **制作対象ロスターの指定方法とボリューム**:
     - **おまかせ派**: 最小試作セット、基本RPGセット（主人公・仲間・街モブ・ザコ・大型ボス）、または「味方○体・モブ○体・ザコ○体・ボス○体」と人数＆サイズ区分（`S/M/L/XL`）だけ指定して中身はAIに企画させる。
     - **こだわり派**: 専用設定ファイル `docs/00_roster_spec.md` に各キャラクター・モブ・ザコ・ボスの役割ランク（`hero/party/mob/enemy/midboss/boss`）・サイズ区分（`S/M/L/XL`）・外見要望を記載する。
- **任意項目（空欄＝「AIおまかせ」で自動補完）**:
  - 具体的な画面解像度指定、主線の好み、キーカラー・色数制限、左右反転の可否など。

### Phase 1: 詳細仕様書への展開（`templates/` → `docs/`）【描画前の完了必須ゲート】
- **コード描画（Phase 2）へ進む前に必ず本フェーズを完了させます**（描画スクリプトを先に書いて仕様書をあと書きする順序逆転は禁止であり、`lint_character_style.py` / `validate_assets.py` が `docs/01〜03` の存在と記述量を検査してブロックします）。
- Phase 0 の回答と `tools/character_blueprints.py` の定量仕様から、`docs/01_art_direction_and_world.md`、`docs/02_color_palette_spec.md`（実体JSONは `assets/palettes/`）、台帳 `docs/03_character_list.md`、および対象アセットの個別仕様書（`docs/characters/<id>.md` 等）を先に確定・保存します。

### Phase 2: 素体＆歩行ブループリントに基づくコード描画（`workspace/01_raw/` → `workspace/02_work/`）
- 人型キャラ（`M`）は `--mannequin <size_preset> <dir> --role <role>` または `--show <size_preset> <taste_preset> <dir>`、大型ボス（`L/XL`）は `--mannequin <size_preset> down --scale <L|XL> --role boss`、歩行アニメは `--walk <size_preset> <dir>` で検証済み素体を確認し、頭:体:足の比率・直立側面姿勢・左右交互の4コマ歩行を守って `workspace/01_raw/<asset_id>/gen_<asset_id>.py` を実装します。

### Phase 3: 自動スタイル検査とセルフレビュー（`workspace/03_preview/`）
- `py tools/lint_character_style.py` で造形アンチパターンがないか機械検査した後、`workspace/03_preview/` に4倍〜8倍拡大プレビュー（チェッカー背景・グリッド・ピボット付き）を出力し、AI自身が画像を読み取ってディテールを磨き上げます。

### Phase 4: 最終書き出し・自動検証（`assets/`）
- `assets/` へ等倍PNGとJSONを書き出し、`py tools/validate_assets.py` でフォーマット・二値アルファ・パレット準拠を保証します。

## 3. 人間とAIの役割分担

| フェーズ | 人間（ディレクター／開発者） | AIエージェント |
| :--- | :--- | :--- |
| **Phase 0: 初期方針決定** | 視点・世界観・サイズ規格・テイスト等の選択 | アンケート実施（または記入シート読取）、`00_project_brief.md` 作成 |
| **Phase 1: 詳細仕様策定** | 提案された仕様・パレットの確認と承認 | `character_blueprints.py` 準拠の技術仕様書とパレットJSONの生成 |
| **Phase 2: コード描画** | キャラクター個性・モチーフの指示 | 素体ブループリントに基づく精密描画スクリプト実装（4方向・アニメ含む） |
| **Phase 3: 検査・視覚確認** | `03_preview/` の確認、好みに関する微調整指示 | `lint_character_style.py` パス確認、視覚セルフレビューと改善反復 |
| **Phase 4: 検収・納品** | 最終承認、ゲームエンジンへの組み込み | `assets/` へのクリーン出力、`validate_assets.py` による品質保証 |
