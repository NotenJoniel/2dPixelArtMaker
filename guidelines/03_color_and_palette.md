# 03. カラー設計・パレット管理ルール

ピクセルアートにおいて「色」は解像度の低さを補い、世界観の統一感とゲームプレイ上の視認性を支える最重要要素です。コード描画ではRGB値を自由に指定できてしまうからこそ、**必ず定義済みパレット（名前付きキーまたはHEXリスト）からのみ色を参照する**運用を徹底します。

---

## 1. マスターパレット運用の原則

1. **ハードコードRGBの禁止**
   - 描画スクリプト内で `(123, 45, 67)` のようなアドホックなRGB値を直接乱造してはならない。
   - `assets/palettes/` に保存されたパレットファイル（`.json` または `.hex`）を読み込み、意味のある色名キー（例: `skin_light`, `skin_base`, `skin_shadow`, `outline_dark`）で指定する。
2. **プロジェクト総色数の目安**
   - **レトロ制限系**: 16色 〜 32色（例: PICO-8 や 16bit小規模パレット相当）
   - **標準インディー2D系**: 32色 〜 64色（汎用マスターパレット＋属性エフェクト色）
   - **リッチ・多バイオーム系**: 64色 〜 128色（共通ベースパレット＋ステージ固有環境パレット）
3. **1スプライトあたりの色数目安**
   - 小型アイコン・`16x16`〜`32x32` キャラ：**4〜8色**（主線1色＋メイン3階調＋サブ2〜3色）
   - 標準 `48x48`〜`64x64` キャラ：**8〜16色**
   - 色数を絞ることで、別キャラ同士が並んだ際の一体感が生まれ、色替えバリエーション（2Pカラー、毒状態、氷結状態、レアモンスター化）もパレット差し替えだけで実現できる。

---

## 2. 色相シフト（Hue Shifting）のルール

ベースカラーから「明るい色（ハイライト）」と「暗い色（影）」を作る際、単純に白や黒を混ぜて明度（Value）だけを上下させると、くすんだ生気のない色になります。必ず**色相（Hue）と彩度（Saturation）を連動して動かす**「色相シフト」を行います。

```text
[寒色（青・紫：約210°〜270°）]  ←── 影方向 ── [ベースカラー] ── 光方向 ──→ [暖色（黄：約50°〜60°）]
   ・明度(V)を下げる                                                      ・明度(V)を上げる
   ・彩度(S)を少し上げる(または維持)                                      ・彩度(S)を少し下げる
```

### 具体例：緑色の葉・草原ランプ（4階調）
- **Highlight（光）**: `#A8E65C`（黄緑寄りへ色相シフト、高明度）
- **Base（基本色）**: `#58B848`（基準の緑）
- **Shadow 1（1影）**: `#2E7D5B`（青緑・シアン寄りへ色相シフト、中低明度）
- **Shadow 2（深影/色トレス線）**: `#1B434D`（深い青紫寄りへシフト、低明度）

### 具体例：肌色ランプ（3階調＋主線）
- 肌色の影を単なる「茶色・灰色」にすると泥汚れのように見えるため、**赤み・紫み（血色感）**の方向へ色相を寄せる。
- 例: Highlight `#FFE4C4` → Base `#F4B895` → Shadow `#C97B6E` → Outline `#5C2C38`

## 3. 純黒（`#000000`）と純白（`#FFFFFF`）の扱い

- **純黒 `#000000` は原則として通常塗りに使わない**:
  - 暗闇の背景上で黒い主線が完全に消えてしまうほか、色味が死んで重苦しくなるため、最暗色（主線・最深影）には **`#141020`（濃紫黒）や `#121824`（濃紺黒）** のような、わずかに色味を含んだダークカラーを設定する（レトロ8bit風で黒背景前提の場合を除く）。
- **純白 `#FFFFFF` は最強のアクセント用に温存する**:
  - 瞳のハイライト、刃の閃光、被弾フラッシュ、最重要UIテキストなど、画面内で最も目立たせたい数ピクセルに限定し、白い服や雲のベースカラーには `#E6ECF5` などの明るいグレーブルーを使う（そうしないと白服にハイライトを入れられなくなる）。

## 4. 視認性を守る「明度・彩度の階層（Value Hierarchy）」

ゲーム画面では「背景」「足場（地形）」「キャラクター・敵・弾」「UI・エフェクト」が重なります。これらが同化して見失う事故を防ぐため、レイヤーごとに使用できる明度コントラストと彩度のレンジを分けます。

| レイヤー階層 | 明度コントラスト（明暗差） | 彩度（鮮やかさ） | 主線の強さ | 設計意図 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 遠景・背景壁** | 低い（狭い明度幅に収める） | 低い（くすませる・空気遠近） | なし（または背景色に近い線） | 奥へ引っ込め、手前の邪魔をしない |
| **2. 踏める地形・床・壁** | 中〜高（境界エッジを明確に） | 中程度 | 接触面（床の上端等）を強調 | どこに乗れてどこが壁か瞬時に分かる |
| **3. キャラ・敵・アイテム** | **高い（明るい光と濃い影）** | **中〜高（固有色を明確に）** | **明確な1px主線** | どんな背景の上でも埋もれない |
| **4. 敵弾・危険予兆・VFX・UI** | **最高（発光・白黒の極値）** | **最高** | 高コントラスト縁取り | 0.1秒でプレイヤーが反応できる |

> **グレースケール確認ルール**: キャラクターを背景タイルの上に置いた状態で画像をグレースケール化したとき、輪郭とシルエットがはっきり分離して見えるかを必ず意識します。

## 5. パレットファイルの標準フォーマット

`assets/palettes/` には、以下の2形式のいずれか（推奨は両方）を配置します。

1. **`.hex` 形式（Aseprite / Lospec 互換テキスト）**: 1行に1色（`#` なし6桁HEX、例: `181425`）。汎用ツールへの読み込み用。
2. **`.json` 形式（コード描画用セマンティックパレット）**: 色ランプ（階調配列）や用途名で引ける構造。`tools/pixel_canvas.py` から直接ロードして使用します。

```json
{
  "name": "standard_fantasy_32",
  "transparent_chroma": "#FF00FF",
  "colors": {
    "outline_dark": "#181425",
    "white_pure": "#FFFFFF",
    "skin_light": "#FFE3C6",
    "skin_base": "#F2B694",
    "skin_shadow": "#C4786B",
    "hero_blue_light": "#63C7FF",
    "hero_blue_base": "#3273D6",
    "hero_blue_shadow": "#1D3B8B"
  },
  "ramps": {
    "skin": ["skin_light", "skin_base", "skin_shadow", "outline_dark"],
    "hero_blue": ["hero_blue_light", "hero_blue_base", "hero_blue_shadow", "outline_dark"]
  }
}
```
