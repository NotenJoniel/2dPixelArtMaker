# 05. アニメーション・スプライトシート規約

本ドキュメントでは、コードによるピクセルアニメーション制作（パーツ駆動アニメーションおよびコマ打ちアニメーション）と、スプライトシート書き出しの標準ルールを定めます。

---

## 1. ドット絵アニメーションで「パーツ回転」を扱う際の重要注意

通常の高解像度2Dイラスト（SpineやLive2D等）と異なり、低解像度のピクセルアートでパーツ画像を単純に任意角度（例: `17°` や `33°`）で回転させると、ピクセルの四角い角が斜めに傾いてガタガタに崩れたり、Mixelsのような違和感が発生します。

これを防ぐため、プロジェクトのスタイルに応じて以下のいずれかのアプローチを採ります：

1. **アプローチA：整数ピクセル平行移動＋差分パーツ切り替え（最もドット絵らしい・推奨）**
   - 呼吸・歩行・走行の上下動（ボビング）や腕の前後スイングを、**`1px`〜`3px` の整数座標オフセット移動**と、数パターンの角度別パーツ描画（例：腕の「下げ」「前振り」「振り上げ」をコードで各角度ごとにクリーンなドットとして再描画）で表現する。
   - どのフレームで止めても完璧な1xピクセルグリッドと美しい1pxアウトラインが維持される。
2. **アプローチB：エンジン側でのリアルタイム骨格回転（ボーン制御重視）**
   - ゲームエンジン側でボーン回転を行う場合は、`assets/characters/<id>/parts/` のパーツと `<id>_meta.json` の `pivot`・親子階層をそのまま利用する。
   - エンジン側のカメラ設定で「ピクセルパーフェクト・レンダリング（低解像度レンダーターゲットへの描画）」を有効にすることを推奨する。

## 2. 標準アニメーションステートとフレーム数目安

ジャンルに応じて必要なステートを選択します。ステート名はすべて小文字 `snake_case` で統一します。

| ステートID | 用途 | 標準フレーム数 | 推奨FPS目安 | ループ | 動きづくりのコツ（コード制御指針） |
| :--- | :--- | :---: | :---: | :---: | :--- |
| `idle` | 待機・呼吸 | `4`（最小`2`） | `4`〜`6` | `true` | 胸(`torso_upper`)と頭を1px上下させ、1フレーム遅れて髪やマントの先端を1px揺らす（フォロースルー）。 |
| `walk` | 歩行 | `6` または `8`（最小`4`） | `8`〜`10` | `true` | 接地(Contact)→沈み(Down)→通過(Passing)→伸び(High Point)の上下1〜2pxの頭位置変化を入れる。手と足は逆位相に振る。 |
| `run` | 走行・ダッシュ | `6` または `8` | `12`〜`14` | `true` | 上半身を進行方向へ1〜2px前傾させ、両足が地面から浮く瞬間を作る。 |
| `jump_up` | ジャンプ上昇 | `1`〜`2` | `8` | `false` | 体を縦に少し伸ばし、手足を軽く引き上げる。マントや髪は下方向へなびかせる。 |
| `jump_fall` | 落下中 | `2` | `8` | `true` | 髪やマントが上方向へ浮き上がり、着地に備えて視線を下げる。 |
| `attack_01` | 通常攻撃（斬撃等） | `4`〜`6` | `12`〜`16` | `false` | **溜め（予備動作 1〜2f）→ 振り抜き＋スメア（軌跡残像 1f）→ フォロースルー・硬直（2f）** の緩急を必ずつける。 |
| `hit` | 被ダメージ | `2` | `10` | `false` | のけぞりポーズ＋`damage` 目差分。白フラッシュ処理はエンジン側シェーダーまたは専用フレームで行う。 |
| `dead` | 戦闘不能・ダウン | `3`〜`5` | `8` | `false` | 膝をつく → 倒れ込む → 接地して少し跳ねて静止。 |

## 3. 生命感を出す3つのドットアニメ技法

コードで複数フレームを生成する際、以下の要素を入れるだけで「機械的な往復運動」から一気にプロ品質のアニメーションになります。

1. **予備動作（Anticipation）と残像（Smear）**
   - 剣を振る直前に1フレームだけ体を後ろに引く（溜め）。次のフレームで一気に振り抜き、刃の通り道に白や水色の三日月状の軌跡ドット（スメア）を1フレームだけ描く。
2. **二次動作・遅れ追従（Secondary Action / Overlap）**
   - 頭が下がった瞬間ではなく、**1フレーム遅れて**後ろ髪（`hair_back`）・アホ毛・耳・マントの裾が追従して動くように位相をずらす（`sin(t - phase_offset)` 等でコード表現が非常に容易）。
3. **接地位置（足裏ライン）の固定**
   - キャンバス内の足元基準ライン（`origin` の Y座標、例: `64x64` キャンバスの `y = 60`）を全フレームで統一する。待機や歩行で地面の高さが上下にズレて浮いて見えないように注意する。

## 4. スプライトシートの配置規約

複数フレームを1枚の画像に結合するスプライトシート（`spritesheets/`）は、どのゲームエンジンでも等間隔グリッド切り出しができるよう以下の規則に従います。

- **レイアウト構造**:
  - **横方向（列 / Columns）**: フレームの進行（左から右へ `frame 0, 1, 2, ...`）
  - **縦方向（行 / Rows）**: アニメーションステート別（または4方向別：`idle_down`, `idle_left`, `idle_right`, `idle_up`, ...）
- **セルサイズの統一**:
  - シート内の全セルは同一サイズ `cell_size: [cell_w, cell_h]` に揃える。
  - 武器の振り抜きで通常サイズ（例 `64x64`）からはみ出す場合は、シート全体のセルサイズを余裕のあるサイズ（例 `96x64` または `96x96`）に拡張し、キャラの足元基準点（`origin`）が全セルで同じ相対座標になるように配置する。
- **セル間パディング（Padding）**:
  - デフォルトは `0` px（等倍ニアレストネイバー描画環境では隣接ピクセルにじみが起きないため最も扱いやすい）。テクスチャフィルタリングやミップマップを使う環境向けに余白が必要な場合は `padding: 1` または `2` px（透明ピクセル）を指定し、付随JSONに明記する。
